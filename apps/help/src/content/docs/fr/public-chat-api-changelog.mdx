Cette page liste chaque version de l'API de chat publique. La version courante est la
**2.0**. Les versions mineures ajoutent des éléments et gardent les clients existants
fonctionnels. Les versions majeures peuvent casser des clients et viennent avec une période
de dépréciation. Voir la
[politique de versions et de dépréciation](/fr/public-chat-api-versioning).

## 2.0 (2026-10-30)

### Modifié

- Toutes les routes passent sous `/public/v2/agents/{embedToken}/`. Les requêtes, les
  réponses et les erreurs gardent la forme de la 1.2, sauf le flux ci-dessous.
- [Envoyer un message et recevoir la réponse en flux](/fr/public-chat-api#envoyer-un-message-et-recevoir-la-réponse-en-flux)
  passe par `POST /public/v2/agents/{embedToken}/sessions/{sessionId}/stream`. Le message
  voyage dans le corps JSON. Il n'atteint donc plus les limites d'URL ni les journaux
  d'accès. La réponse est le même flux.
- Un corps sans objet `payload` termine le flux avec l'erreur `Invalid request body`.

### Supprimé

- La route `GET .../messages/stream?q=...` et son erreur de flux `Invalid query format`.
  La v2 ne les sert pas.

### Déprécié

- La version 1 (`/public/v1/...`). Elle répond comme en 1.2 jusqu'au **2027-05-31**. Après
  cette date, ses chemins répondent `404`.

### Migration

- Remplacez `/public/v1/` par `/public/v2/` dans chaque URL. Les identifiants et les jetons
  de session créés sur la v1 restent valables sur la v2.
- Envoyez le message à `POST .../sessions/{sessionId}/stream` en corps JSON,
  `{ "payload": { "content": "..." } }`, avec l'en-tête `Content-Type: application/json`,
  au lieu du paramètre `q` de la route `GET`.

## 1.2 (2026-10-29)

### Modifié

- Une session vidée par la règle de rétention de l'espace de travail est maintenant
  refusée. Chaque route de session répond `410` avec `message: "Session expired"` et
  `code: "SESSION_EXPIRED"`. Avant, la session répondait `200` avec des messages au
  `content` vide.

### Migration

- Traitez un `410` sur une route de session comme un `401` : oubliez la session stockée et
  créez-en une nouvelle. Vous pouvez dire à l'utilisateur que la conversation précédente a
  expiré.

## 1.1 (2026-10-22)

### Ajouté

- `payload.variables` sur [créer une session](/fr/public-chat-api#créer-une-session) : un
  agent peut déclarer des `{{variables}}` dans ses instructions, et l'appelant fournit leurs
  valeurs à la création de la session. Chaque valeur est substituée dans le prompt de
  l'agent avant chaque réponse.
- Une variable déclarée sans valeur de l'appelant repart sur le **défaut** configuré dans
  l'onglet Embed de l'agent.
- Quand une variable déclarée n'a ni valeur de l'appelant ni défaut, la session est refusée
  avec un `400` dont le corps porte `code: "MISSING_PROMPT_VARIABLES"` et la liste `missing`
  des noms de variables.

### Migration

- Aucune. Les clients existants continuent de fonctionner : `payload.variables` est
  optionnel, et un agent qui ne déclare aucune `{{variable}}` se comporte exactement comme
  avant.

## 1.0 (2026-09-09)

### Ajouté

- Première version publiée de l'API de chat publique, sous `/public/v1/agents/{embedToken}/`.
- Cinq routes : configuration de l'agent, création d'une session, lecture d'une session,
  lecture du HTML des cartes MCP App, envoi d'un message avec réponse en flux.
- La [page de référence](/fr/public-chat-api) documente les routes, les événements envoyés
  par le serveur, les codes d'erreur, le comportement CORS et les limites.

### Migration

- Aucune. Il s'agit de la première version publiée du contrat.
