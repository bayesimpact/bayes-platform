**Embed** lets you make a **conversation agent** available to people outside the
platform, in two ways:

- as a **chat widget** on your own website: you turn embedding on, copy a small
  `<script>` **snippet** into your site, and the agent appears as a chat bubble (or a
  side panel) that your visitors can talk to;
- as a **standalone public page**: the platform serves the same chat, full screen, at
  a **public page link** you can share directly or print as a **QR code**. No website
  is needed, which suits a pilot, an event or a test access.

Embedding is configured in the editor of a **conversation agent** (a form agent is
one too), in **Studio**: **Embed** sits in the editor's left menu, under **More**. It
is not part of the agent's draft: it opens in a full page with its own **Save**, and
your changes apply to the agent **in production** as soon as you save them. It has no
versions in the [version history](/en/agent-version-history). It's an optional
feature: the entry only appears when your workspace has embedding enabled. Extraction
agents don't have it.

> **Ask to have it enabled.** Embedding is turned on per workspace. If your
> conversation agent's editor has no **Embed** entry under **More**, the feature isn't
> enabled for your workspace yet. Contact the Bayes team to request it.

## How embedding works

- Each conversation agent has its own **embed token**. The `<script>` tag under
  **Widget on a website** carries it: adding that tag to a web page loads the chat
  widget for that agent.
- The same token gives the agent a **public page** link. Anyone who opens it gets the
  full chat, without any host website. It also gives the **Base URL** of the
  [public API](/en/public-chat-api), to build your own chat interface.
- The tag, the link and the URL exist whether or not embedding is on, but the widget,
  the public page and the public API only work once **Enable embed** is on. Turning it
  off takes all three offline immediately, which is how you end a temporary access.
- You can **customize the appearance** (title, logo, brand color) plus a few optional
  `data-` attributes on the script tag.
- An optional **banner text** stays pinned above the conversation, on the public page
  and in the widget, so visitors always see the context (for example *Test version,
  for the pilot team only*) even if the link is forwarded.
- Visitors talk to the agent's **published** version. Changes in the draft reach them
  once you save the draft as a version.

## Step by step

### 1. Open a conversation agent

In **Studio**, open the **conversation** agent you want to embed (from the **Agents**
list in the left sidebar, or its card on the workspace overview). Its page opens. You
need permission to manage the agent.

### 2. Open the agent editor

At the top right of the agent's page, click **Edit**. The button shows what the editor
opens on: a **Draft** badge, or the published version (for example **v3**).

### 3. Open Embed

In the editor's left menu, under **More**, click **Embed** (it carries an
external-link icon: it opens over the editor). **Embed** opens in a full page. Its
header reads *These settings are not part of the draft: they apply in production as
soon as you save.*, with **Close** and **Save** at the top right (they also show at
the bottom of the page). If you don't see **Embed**, the feature is either not enabled
for your workspace or you're not on a **conversation** agent (see Troubleshooting).

### 4. Enable embed

Turn on **Enable embed**. Its description reads *Makes `<agent name>` available outside
the platform: the widget, the public page and the public API. When off, all three
stop working.*

### 5. Customize the appearance

Under **Appearance** (*Shown in the header of the widget and of the public page.*),
four optional fields control how the chat looks:

- **Widget title**: the title shown in the chat header. Left empty, it **defaults to
  the agent's name**.
- **Logo URL**: the URL of a logo image shown in the chat header (e.g.
  `https://example.com/logo.png`).
- **Brand color**: the primary color of the chat header. Pick it with the color
  swatch or type a **hex value** (e.g. `#2563eb`).
- **Banner text**: an optional notice pinned above the conversation, on the public
  page and in the widget. State the context there: a test version, the intended
  audience, a validity period. Leave it empty to show no banner.

### 6. Put the widget on a website

Under **Widget on a website**, you'll find a read-only `<script>` tag. Click the
**copy** button next to it, then, as the description says, *paste this `<script>` tag
before the closing `</body>` tag on each page where the chat widget must appear.*

The hint lists **optional attributes** you can add to the tag:

- **`data-color`**: the chat button color (e.g. `#2563eb`).
- **`data-locale`**: the widget language (e.g. `fr`).
- **`data-display-mode`**: set to `drawer` for a side panel instead of a bubble.
- **`data-hint`**: a tooltip shown on load and on hover (e.g. `Need help?`).

Below, **Allowed origins** reads *Leave empty for now.* The widget calls the platform
from the platform's own address, not from your website, so a list without that
address blocks the widget. The check of the website that shows the widget is not
available yet. **Read the widget guide** opens this page.

### 7. Share the public page

Under **Public page**, copy the link with the **copy** button. Share it as a link or a
QR code when you have no website to host the widget. The page only works while
embedding is enabled. Append `&locale=fr` to force the language of the page.

### 8. Use the public API

Under **Public API**, copy the **Base URL**: every route of the API starts with it,
and it contains the embed token of this agent. **Read the API reference** opens the
[public chat API](/en/public-chat-api) reference.

### 9. Save

Click **Save**, at the top or at the bottom of the page. The button stays greyed out
until you've made a change. Once you've changed something, **Close** becomes
**Cancel**. Cancel, the close cross, Escape or a click outside the page with unsaved
changes opens the **Unsaved changes** dialog, which asks whether to **Discard** them.

### 10. Confirm

The **Apply these settings now?** dialog reads *These settings do not go through the
draft: they apply to the agent **in production** as soon as you save.* Click **Save**
to apply them, or **Cancel** to go back to the page. Your changes (enabled state,
allowed origins, title, logo, color and banner) then take effect for the widget, the
public page and the public API.

## Tips

- Keep **Enable embed** off until your appearance and banner are set, so the widget
  only goes live once it's ready.
- Leave **Allowed origins** empty for now: a list without the platform's own address
  blocks the widget.
- Use `data-display-mode="drawer"` when you want a side panel rather than a floating
  bubble, and `data-locale` to force the widget's language.
- The **Widget title** falls back to the agent's name: set it explicitly if you want
  a different heading for visitors.
- For a temporary access shared by link or QR code, set a **Banner text** that says
  who the agent is for, then turn **Enable embed** off when the access ends.
- The widget keeps the conversation across visits. Visitors start a new one with the
  **new conversation** button in the chat header. Your site can do the same, for example
  on logout, by calling `window.__agentStudioResetSession()`.

## Troubleshooting

- **I don't see Embed in the editor**: it appears under **More** only for
  **conversation** agents (form agents included), only when the workspace has
  embedding enabled, and only if you can manage the agent. Extraction agents never
  show it.
- **The widget doesn't appear on my site**: check that **Enable embed** is on and
  saved, that the tag is pasted before `</body>`, and that **Allowed origins** is
  empty.
- **The header shows the agent's name, not my title**: **Widget title** is empty, so
  it defaults to the agent's name; enter a title, then **Save** and confirm.
- **The public page shows "not available"**: **Enable embed** is off, or **Allowed
  origins** is not empty. Turn embedding on, clear the origins list, then **Save** and
  confirm.
- **The banner doesn't show**: **Banner text** is empty, or you didn't save and
  confirm. The banner only appears when the text is set.
- **Visitors don't see my latest changes to the agent**: the widget runs the
  published version. Open **Manage versions** in the editor and **Save version**.
- **Related:** the embedded widget is a conversation agent; see
  [Add a conversation agent](/en/add-a-conversation-agent) to configure what it says.
