# Evaluation API Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give Evaluation an API of its own: an `eval` module in `apps/api` whose controllers serve every route of `packages/eval-contracts` under `eval/` and check requests and responses with their Zod schemas.

**Architecture:** The generic layer of `apps/api/src/common/schema-route/` already serves the Desk. It stops taking its route types from the Desk contracts, so a route of any contracts package fits. `apps/api/src/domains/eval/` holds standalone controllers, a folder per area of the contracts, whose handlers are copies of the logic Evaluation calls today. The entities, services, repositories and workers stay in `domains/evaluations/` and `domains/review-campaigns/`. The contracts get a CommonJS build so the API can require them.

**Tech Stack:** NestJS 11, Zod 4, Jest with `@swc/jest`, supertest, TypeScript 7 (`tsc`), dependency-cruiser.

**Spec:** `docs/superpowers/specs/2026-11-24-eval-api-design.md`

**Model to follow:** the Desk did the same on 2026-11-23. Read `docs/schema-routes.md` first, then one area of `apps/api/src/domains/desk/` (`extractions/` has a controller, mappers and specs). `docs/superpowers/plans/2026-11-23-desk-api.md` is the plan this one copies.

## Global Constraints

- No service and no repository changes. If a handler cannot be written without one, stop and ask.
- No existing endpoint changes its behaviour, guards or response. Existing specs stay as they are. No old controller or old route is removed.
- In other domains, only `*.module.ts` files change (to export a provider).
- `src/domains/eval/` never imports a `*.entity.ts` of another domain, type imports included. Specs and factories are excepted. Type a record from the return type of the service that gives it, or from `src/common/context/request.interface.ts`.
- `src/domains/eval/` never imports a file of `src/domains/desk/`, and the reverse. A mapper the Desk has is copied.
- Evaluation paths start with `eval/`. Method, params, body, response and the `review_campaign_tester` segment stay.
- Each handler checks the permission, on the resource, with the context list, of the endpoint it copies. Read them from that endpoint, never from a table of this plan or of the spec. Status codes and tracked activities are those of that endpoint.
- Every schema refusal answers 400. Handlers keep the checks a schema cannot express, with today's status codes, and drop the ones the schema guarantees. The contracts are not loosened.
- `eval-contracts` imports nothing but Zod. `apps/eval` changes only through the contracts.
- Files in `src/domains/eval/` drop the `eval-` prefix. Classes keep the `Eval` prefix (`EvalConversationRunsController`).
- Never run `npm install`. No new permission, grant or migration. Nothing under `/public`.
- `apps/api/CLAUDE.md` applies: `@Controller()` with no prefix and no guard of its own, descriptive loop variables, `Logger`, factories for test data, neutral sample data, value imports with the `biome-ignore` comment for injected classes.
- The repository is public: no private repository named in code, commits or the PR.
- Run single specs with `npx jest --colors --runInBand --forceExit <path>` from `apps/api`, never piped. This worktree has no environment: the specs use the shared test database, so start no dev server.
- One commit per task, local. Push only when Alexis says so.

## Review Focus

1. A malformed `columnFilters` (`columnFilters={bad`) answers 400, not 500: `JSON.parse` throws inside the codec today. Test in Task 5.
2. An empty `page` or `limit` (`page=`) answers 400: `z.coerce.number` reads it as 0 today. Tests in Tasks 4 and 5.
3. A context resolver the new context module forgets fails at the first request, not at start. Each route with a context has a test with an unknown id that answers 404, never 500. Tests in the `auth.spec.ts` of Tasks 3 to 8.
4. A record richer than the factories' default still passes the response schema: a failed run with its error fields, a graded run record, a campaign with every optional field set, a reviewer's session whose messages hold tool parts and an attachment, a report of a campaign with no session. Tests in Tasks 4 to 8.
5. A tester's reply stream on a campaign that is closed answers what it answers today, before any frame goes out. Test in Task 8.

- Produces, in `schema-route.types.ts`, the types every other file of the layer and every handler use from now on:

```ts
export type SchemaRouteMethod = "get" | "post" | "put" | "patch" | "delete"

type RouteBase = {
  path: string
  getPath: (params?: Record<string, string>) => string
}

/** A route declared with the `defineSchemaRoute` of any contracts package. */
export type AnySchemaRoute = RouteBase & {
  method: SchemaRouteMethod
  schemas: { params: z.ZodObject; query: z.ZodObject; body: z.ZodObject; response: z.ZodObject }
}

/** A route declared with the `defineStreamRoute` of any contracts package. */
export type AnyStreamRoute = RouteBase & {
  method: "get" | "post"
  schemas: { params: z.ZodObject; query: z.ZodObject; body: z.ZodObject; event: z.ZodType }
}
```

The fixture routes of `schema-route.spec.ts` may keep the `defineSchemaRoute` of the Desk contracts. `SchemaRouteInput` and `SchemaRouteResponse` keep their definitions, on the new types. If a Desk or Evaluation route does not fit a type above, widen the type, never cast in a handler.
