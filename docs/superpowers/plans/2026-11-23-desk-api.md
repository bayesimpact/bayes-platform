# Desk API Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give the Desk an API of its own: a `desk` module in `apps/api` whose controllers serve the 42 routes of `packages/desk-contracts` under `desk/` and check requests and responses with their Zod schemas.

**Architecture:** A generic layer in `apps/api/src/common/schema-route/` reads the `schemas` of a route: one decorator sets the method, path, guards, permission and response check of a handler. `apps/api/src/domains/desk/` holds standalone controllers, one per area of the contracts, whose handlers are copies of the logic the Desk calls today, with the session type fixed to `live`. The contracts get a CommonJS build so the API can require them.

**Tech Stack:** NestJS 11, Zod 4, Jest with `@swc/jest`, supertest, TypeScript 7 (`tsc`), dependency-cruiser.

**Spec:** `docs/superpowers/specs/2026-11-23-desk-api-design.md`

## Global Constraints

- No service and no repository changes. If a handler cannot be written without one, stop and ask.
- No existing endpoint changes its behaviour, guards or response. Existing specs stay as they are.
- In other domains, only `*.module.ts` files change (to export a provider).
- `src/domains/desk/` never imports a `*.entity.ts` of another domain, type imports included. Type a record from the return type of the service that gives it, or from `src/common/context/request.interface.ts`.
- Desk paths start with `desk/`. Method, params, body, response and the `live` segment stay.
- Each Desk handler checks the permission and the resource of the endpoint it copies (table in the spec). Status codes and tracked activities are those of that endpoint.
- Every schema refusal answers 400. Handlers keep the checks a schema cannot express, with today's status codes, and drop the ones the schema guarantees. The contracts are not loosened.
- `desk-contracts` imports nothing but Zod. `apps/desk` changes only through the contracts' paths.
- Never run `npm install`. No new permission, grant or migration. Nothing under `/public`.
- `apps/api/CLAUDE.md` applies: `@Controller()` with no prefix, descriptive loop variables, `Logger`, factories for test data, value imports with the `biome-ignore` comment for injected classes.
- The repository is public: no private repository named in code, commits or the PR.
- Run single specs with `npx jest --colors --runInBand --forceExit <path>` from `apps/api`, never piped.
- After a change to the contracts, run `bayes wt up` before testing in the worktree environment.

## Review Focus

1. A POST route that reads no body, called with no body and no `Content-Type`, passes the input guard. Test in Task 2.
2. A caller with no token and a malformed id gets 401, not 400: authentication runs before the input guard. Test in Task 2.
3. A record richer than the factories' default still passes the response schema: a message with tool parts, a form, an attachment and sources; an extraction run that failed, with `errorCode` and `errorDetails`; a CSV record with an error. Tests in Tasks 4, 6 and 7.
4. `request.params` stays as Express gave it after the input guard runs, since the context resolvers read it. Test in Task 2 (a route with a context).
5. A tracked activity is recorded once by a Desk route, with the action of the route it copies. Test in Task 4 (conversation creation).

### Task 2: `common/schema-route/`

**Files:**

**Interfaces:**
- Consumes: `AnySchemaRoute`, `AnyStreamRoute` from `@caseai-connect/desk-contracts`.
- Produces:

```ts
// schema-route.types.ts
export type SchemaRoutePermission =
  | { key: CatalogPermission; on: PermissionResourceType }
  | "signed-in"
export type SchemaRouteOptions = {
  permission: SchemaRoutePermission
  context?: ContextResource[]
  activity?: TrackActivityOptions
  /** Defaults to Nest's: 201 for a POST, 200 otherwise. A stream answers 200. */
  status?: number
}
export type SchemaRouteInput<TRoute extends AnySchemaRoute | AnyStreamRoute> = {
  params: z.output<TRoute["schemas"]["params"]>
  query: z.output<TRoute["schemas"]["query"]>
  payload: /* z.output of the body's `payload`, `undefined` when the route reads no body */
}
export type SchemaRouteResponse<TRoute extends AnySchemaRoute> =
  z.input<TRoute["schemas"]["response"]>

// schema-route.decorator.ts
export function SchemaRoute(
  route: AnySchemaRoute | AnyStreamRoute,
  options: SchemaRouteOptions,
): MethodDecorator

// route-input.decorator.ts: `@RouteInput() input: SchemaRouteInput<typeof route>`
export const RouteInput: () => ParameterDecorator

// test/schema-request.ts
export const testSchemaRequester: (app: INestApplication<App>) => <T extends AnySchemaRoute>(params: {
  route: T
  pathParams?: Record<string, string>
  token?: string
  query?: Record<string, string>
  body?: unknown
}) => Promise<Omit<request.Response, "body"> & { body: z.output<T["schemas"]["response"]> }>
/** Checks the status, and that the body is exactly what the route's response schema keeps. */
export const expectSchemaResponse: (route: AnySchemaRoute, response: request.Response, status?: number) => void
```

Decisions:
- `@SchemaRoute` uses `applyDecorators`. Guard chain: `JwtAuthGuard`, `UserGuard`, the input guard, then `ResourceContextGuard` when `context` is set, then `CheckPermissionGuard` when the permission is not `"signed-in"`. A stream route (`"event" in route.schemas`) uses `@Sse(path, { method: RequestMethod.POST })` with `@HttpCode(200)` and no response interceptor.
- The input guard reads the route from metadata, parses `request.params`, `request.query` and `request.body ?? {}`, and stores the result on the request under one key. It never rewrites `request.params`. On failure: `BadRequestException` with `{ statusCode: 400, message: "Invalid request", error: "Bad Request", issues: [{ path, code, message }] }`, where `path` starts with `params`, `query` or `body`.
- The interceptor `safeParse`s the handler's answer with `route.schemas.response`. On failure it logs the route and the issue paths with `Logger` and throws `InternalServerErrorException`.

- [ ] **Step 1: Write the failing specs** in `schema-route.spec.ts`, on a Nest test app with a fixture controller and two fixture routes declared with `defineSchemaRoute` (`post fixtures/:fixtureId` with a strict body `{ name: z.string() }` and a response `{ id: z.uuid() }`; `post fixtures/:fixtureId/reset` with no body), with `JwtAuthGuard` and `UserGuard` overridden as `setupUserGuardForTesting` does:
  - `answers 400 with issues for an id that is not a UUID` (`issues[0].path` is `["params", "fixtureId"]`)
  - `answers 400 for a body key the schema does not declare`
  - `answers 400 for a query key when the route declares none`
  - `answers 401 before 400 when there is no token`
  - `accepts a POST with no body on a route that reads none`
  - `gives the handler the parsed params and payload`
  - `leaves request.params as Express gave them`
  - `strips a response field the schema does not declare` (the handler returns `{ data: { id, secret } }`)
  - `answers 500 and logs when the response breaks the schema`

- [ ] **Step 3: Implement the five files and `test/schema-request.ts`**
